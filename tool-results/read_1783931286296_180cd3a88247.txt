    14→    14→## 1. PROJECT OVERVIEW
    15→    15→
    16→    16→**Meridian Hotel** is a full-featured Hotel Property Management System (PMS) built for a **4-star, 48-room hotel in Kathmandu, Nepal**. Features NPR currency, Bikram Sambat calendar, 13% VAT + 10% service charge, and Nepal-specific business rules.
    17→    17→
    18→    18→**Single-page application** — all 17 modules render at the `/` route and switch via Zustand navigation state. Only `/login` is a separate route.

   179→   179→## 7. KEY ARCHITECTURE PATTERNS
   180→   180→
   181→   181→### 7.1 Navigation System
   182→   182→- **Single-page app**: All modules render at `/` route via `src/app/page.tsx`
   183→   183→- **Auth gate**: `page.tsx` checks `useAuthStore.isAuthenticated` → shows `LoginPage` or `AppShell`
   184→   184→- **Module router**: `AppShell` reads `useNavigationStore.activeModule` → renders corresponding `*Module.tsx`
   185→   185→- **Sidebar-tab linking**: Bidirectional sync between sidebar items and in-module `<Tabs>` via `navigateTo(moduleId, subModuleId)`
   186→   186→- **`navigateTo`**: Sets `activeModule`, `activeSubModule`, and auto-expands sidebar parent
   187→   187→
   188→   188→### 7.2 Data Fetching
   189→   189→- **API helper**: `src/lib/api.ts` → `apiFetch(path, options)` wrapper around native `fetch`
   190→   190→- **Query keys**: `src/lib/queryKeys.ts` → centralized `qk` factory object
   191→   191→- **Pattern**: Every view uses `useQuery({ queryKey: qk.xxx(), queryFn: () => apiFetch('/api/xxx') })`
   192→   192→- **Stale time**: 30 seconds, 1 retry on error
   193→   193→
   194→   194→### 7.3 Cross-Module Cache Invalidation (7 helpers in queryKeys.ts)
   195→   195→| Helper | When to Call | What It Invalidates |
   196→   196→|--------|-------------|-------------------|
   197→   197→| `invalidate.afterCheckIn(qc)` | After guest check-in | rooms, roomsBoard, roomsTypes, roomsAll, roomsCalendar, roomsVacant, vacantRooms, reservations, arrivals, inHouse, departures, dashboard, frontDeskDashboard, guests |
   198→   198→| `invalidate.afterCheckout(qc)` | After guest check-out | Same as check-in + folios |
   199→   199→| `invalidate.afterReservationChange(qc)` | After CRUD on reservation | rooms (all variants), reservations, arrivals, departures, inHouse, dashboards, guests |
   200→   200→| `invalidate.afterFolioChange(qc, guestId?)` | After charge/payment/void | folios, inHouse, departures, dashboards, guestLedger (if guestId), guestFolios (if guestId) |
   201→   201→| `invalidate.afterRoomTransfer(qc)` | After room transfer | rooms (all), reservations, inHouse, dashboards, roomMoves |
   202→   202→| `invalidate.afterAudit(qc)` | After night audit/day close | rooms (all), reservations, folios, inHouse, arrivals, departures, dashboards, operations, guests |
   203→   203→| `invalidate.afterRoomStatusChange(qc)` | After HK status change | rooms (all), dashboards, housekeeping |
   204→   204→| `invalidate.afterFolioCharge(qc)` | After POS charge to room | folios, inHouse, departures, dashboards |
   205→   205→

   372→   372→## 15. CODING CONVENTIONS & RULES
   373→   373→
   374→   374→1. **Single Route**: Only `/` is user-visible. No other routes. `page.tsx` is the module router.
   375→   375→2. **API Routes**: Always route handlers in `src/app/api/`. Client calls via `apiFetch()`. Never use server actions.
   376→   376→3. **Components**: shadcn/ui first. Custom in `shared/`. Module views in `modules/`.
   377→   377→4. **State**: Zustand for client state, TanStack Query for server state. Never mix.
   378→   378→5. **Styling**: Tailwind CSS classes only. No inline styles. Use `cn()` for conditional classes.
   379→   379→6. **Icons**: Lucide React only. No other icon libraries.
   380→   380→7. **No indigo/blue** unless explicitly requested.
   381→   381→8. **Responsive**: Mobile-first, `sm:`, `md:`, `lg:` breakpoints.
   382→   382→9. **Sticky Footer**: `min-h-screen flex flex-col` + `mt-auto` on footer.
   383→   383→10. **Dark Mode**: Supported via `next-themes` with `class` strategy.
   384→   384→11. **Lint**: Must pass `bun run lint` with 0 errors, 0 warnings.
   385→   385→12. **No `bun run build`** — only `bun run dev`.
   386→   386→13. **Port**: Next.js always on 3000. No other ports for main app.
   387→   387→14. **Gateway**: Caddy handles port routing. Mini-services use `XTransformPort` query param.
   388→   388→15. **SDK Usage**: `z-ai-web-dev-sdk` MUST only be used in backend API routes, never client-side.
   389→   389→16. **Diffs Only**: When modifying existing files, use targeted edits, never full rewrites.
   390→   390→17. **WORKLOG**: Every agent must read/append to `worklog.md` using the Task ID format.
