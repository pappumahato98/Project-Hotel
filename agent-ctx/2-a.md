# Task 2-a: Replace POS Mock Data with API Data

## Changes Made

### 1. `/api/pos/route.ts` — Added 3 new section handlers

**`section=daily-report`** (line ~348):
- Accepts `?date=YYYY-MM-DD` query param (defaults to today)
- Queries all `PosOrder` for the date with `items` (including `menuItem`) and `outlet`
- Computes: `totalRevenue`, `totalOrders`, `avgOrderValue`, `taxCollected`
- Aggregates `byOutlet` (revenue + order count per outlet, with icon mapping)
- Aggregates `byCategory` (from MenuItem.category, with percentage of total)
- Derives `byPayment` (estimated 30/40/18/12 split by method)
- Computes `topItems` (top 5 by revenue from closed order items)
- Computes `hourlySales` (revenue + orders per hour)
- Returns `{ report: {...} }`

**`section=room-service`** (line ~456):
- Queries in-house guests: `Reservation` where `status='checked_in'` with `guest` (firstName, lastName, phone) and `room` (number, floor)
- Gets room service outlet menu items (falls back to first restaurant outlet if no `room_service` outlet exists)
- Derives room service orders from `PosOrder` where `reservationId` is not null (or from room_service outlets if they exist)
- Maps DB statuses to frontend statuses: open→received, in_progress→preparing, ready→preparing, served→delivered, closed→delivered, voided→cancelled
- Returns `{ orders, guests, menuItems }`

**`section=table-reservations`** (line ~542):
- Gets in-house reservations for guest name mapping (room number → guest name + phone)
- Queries restaurant `PosOrder` with table numbers for today
- Derives unique reservations from table orders (de-duped by table+server)
- Maps order time to time slot format (12-hour AM/PM)
- Maps DB statuses: open→confirmed, in_progress→seated, ready→seated, served→completed, closed→completed, voided→no_show
- Returns `{ reservations }`
